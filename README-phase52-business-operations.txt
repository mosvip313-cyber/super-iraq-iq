سوبر العراق IQ — المرحلة 52: العمليات الإدارية والولاء والتنبؤ
===========================================================

الأساس
------
هذه الحزمة مبنية على ملفات المرحلة 51 (وتتضمن تغييرات المراحل السابقة). راجع النسخة الاحتياطية قبل الاستبدال، ولا تستبدل بيانات جهاز يعمل فعلياً دون نسخة احتياطية قابلة للاستعادة.

مراجعة الموجود قبل الإضافة
--------------------------
- إغلاق الوردية ومقارنة النقد المتوقع بالفعلي موجود مسبقاً في المحاسبة والورديات؛ أضيف تسجيل الحدث في سجل التدقيق.
- المشتريات والمرتجعات موجودة مسبقاً وتحدّث المخزون محلياً؛ أضيف تسجيلهما في سجل التدقيق.
- النسخ الاحتياطي JSON والاستعادة موجودان مسبقاً؛ أضيف فحص بنية أوضح للنسخة وحقول سلامة إحصائية وتضمين سجل التدقيق والتحويلات.
- لوحة التحكم والتقارير موجودة مسبقاً؛ أضيف قسم الولاء والتنبؤ بالمخزون.
- لا يوجد ربط خادمي موحد مثبت لكل حركات الشراء والمرتجعات والتحويلات. لا تعتبر النسخة هذه مزامنة كاملة متعددة الفروع.

الجديد في هذه المرحلة
--------------------
1. تحويلات المخزون: تسجيل تحويل صادر يخصم الكمية محلياً، وتسجيل تحويل وارد بعد التحقق الفعلي من البضاعة ورقم التحويل. يسجل كل منهما حركة مخزون وسجل تدقيق.
2. الولاء: احتساب نقطة واحدة لكل 10,000 دينار عراقي من إجمالي الفاتورة للعميل المسجل. النقاط المحلية غير قابلة للاستبدال أو الخصم من الفاتورة بعد؛ هذه شاشة متابعة أولية.
3. التنبؤ: متوسط مبيعات آخر 30 يوماً لكل منتج، ثم تقدير الطلب لمدة 14 يوماً واقتراح شراء = max(0, احتياج 14 يوماً - المخزون الحالي). لا يأخذ بالحسبان المواسم أو التوريد أو الحجوزات.
4. سجل التدقيق: تسجيل محلي لأحداث البيع والشراء والمرتجعات وإغلاق الوردية والتحويلات والنسخ الاحتياطي. هذا السجل ليس غير قابل للتلاعب ولا يحل محل سجل تدقيق خادمي.
5. الاستعادة: التحقق من وجود مصفوفات المنتجات والمبيعات والتحقق من بنية بعض الحقول قبل استبدال بيانات الجهاز.

التشغيل
-------
- افتح النسخة وفق طريقة التشغيل المعتادة للمشروع.
- أنشئ نسخة JSON احتياطية قبل الاختبار.
- اختبر التحويل الوارد على نسخة تجريبية، مع التأكد من مطابقة رقم التحويل والكمية فعلياً.
- افحص نقاط الولاء على فاتورة تجريبية مرتبطة بعميل مسجل، ثم راجع سجل التدقيق.
- جرّب استعادة نسخة JSON تجريبية على جهاز/ملف بيانات منفصل أولاً.

الاختبارات المنفذة في بيئة البناء
---------------------------------
- node --check على server/src/server.js: ناجح.
- node --check على apps/admin-web/cloud-integration.js: ناجح.
- استخراج كتل JavaScript المضمنة من index.html وفحصها باستخدام node --check: ناجح.
- تحقق ثابت من وجود روابط التنقل والأقسام الجديدة: ناجح.

ما لم يُختبر
------------
- لم يتم الاتصال بقاعدة Supabase حقيقية.
- لم يتم اختبار جهازين فعليين أو تحقق استلام عبر فروع مستقلة.
- لم يتم تنفيذ اختبار متصفح كامل أو اختبار ضغط/أمان خارجي.
- التحويلات وسجل التدقيق ونقاط الولاء في هذه المرحلة محلية؛ لا تدّعِ أنها متزامنة عبر الأجهزة.

قبل الإطلاق التجاري
-------------------
يجب تطبيق اختبارات قاعدة البيانات الفعلية، وتوحيد الشراء والمرتجعات والجرد والتحويلات في معاملات خادمية، ثم اختبار تعارض عمليتين متزامنتين واستعادة نسخة احتياطية حقيقية.
