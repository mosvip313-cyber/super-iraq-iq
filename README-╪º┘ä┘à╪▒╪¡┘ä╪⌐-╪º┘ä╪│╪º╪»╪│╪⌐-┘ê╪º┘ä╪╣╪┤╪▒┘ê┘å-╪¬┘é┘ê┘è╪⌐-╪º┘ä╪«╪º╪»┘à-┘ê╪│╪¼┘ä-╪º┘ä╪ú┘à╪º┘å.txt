المرحلة 26 — تقوية الخادم وسجل الأمان

ما الذي تغير؟
1) تقييد حجم طلبات JSON إلى 1 ميغابايت، والتحقق من بنية بيانات المزامنة وحجمها قبل التخزين.
2) إضافة حد عام للطلبات، وحدود أشد لطلبات المزامنة والمساعد الذكي.
3) عدم قبول رمز فرع أقصر من 32 حرفاً، والتحقق من صيغة معرّف الفرع.
4) جعل قائمة CORS الافتراضية محصورة بعناوين التطوير المحلية بدلاً من السماح الضمني لأي موقع. في الإنتاج يجب تحديد عناوين الواجهة الموثوقة في CORS_ORIGINS.
5) تسجيل أحداث المزامنة الناجحة، ومحاولات التعارض، والاستعادة، وطلبات المساعد الذكي في security_audit_log دون حفظ كلمات المرور أو الرموز أو محتوى النسخة الاحتياطية.
6) إضافة جدول سجل الأمان إلى server/supabase-schema.sql.
7) توضيح أخطاء JSON والطلبات الكبيرة برسائل مناسبة.

التثبيت:
- حدّث ملفات المشروع من هذه الحزمة.
- نفّذ server/supabase-schema.sql في SQL Editor بمشروع Supabase.
- أنشئ رموزاً عشوائية طويلة وفريدة لكل فرع، ثم ضعها في BRANCH_TOKENS_JSON داخل ملف .env على الخادم فقط.
- اضبط CORS_ORIGINS على عناوين واجهة النظام المسموح لها بالاتصال.
- لا تضع SUPABASE_SERVICE_ROLE_KEY أو OPENAI_API_KEY في ملفات الواجهة أو تشارك ملف .env.

حدود مهمة:
هذه المرحلة تقوّي واجهة API الحالية وسجل أحداثها، لكنها لا تحوّل حسابات الموظفين المحلية إلى جلسات مصادقة مركزية؛ ما زالت صلاحيات الأدوار في الواجهة محلية. لا تنشر النظام كخدمة تجارية متعددة الفروع قبل إضافة مصادقة موظفين مركزية وتطبيق RBAC على كل عملية داخل الخادم، مع اختبار اختراق ومراجعة نشر فعلية.
